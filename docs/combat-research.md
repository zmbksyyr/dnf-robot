## PVF 人偶已有完整攻击链，不需要重做依赖搜索

已确认的链为：召唤物品 → 原 ELF 校验并返回 CMD 47 使用结果 → 客户端 P2P 0x2e
创建指定 AIC → AI 条件树选择 KEY → 职业技能状态／NUT → 攻击物体 → 碰撞、命中、HP 同步。
CMD 47 和 P2P 召唤是不同环节。

高级阿甘左物品在该采集 PVF 中指向 AIC 1561，和普通人偶 417 是不同定义。
高级阿甘左有真实无人继续输入攻击键的自主战斗、掉血和掉落；格斗家 28 号、枪手、
魔法师、圣职者的 AIC／AI／KEY 已静态核对，不能把它们都记为实战通过。
五职业依赖已有 129 项核对，与旧提取共有的 37 项解密哈希一致。

AI 有范围、敌人数、技能可用性、HP/MP、队友条件及事件衔接；KEY 包含动作与时序。
职业脚本负责具体攻击：例如鬼剑士拔刀斩创建 24337，再从所属角色读取技能／装备；
男魔法师旋风创建 24201，联网参数布局不同。不能为所有技能套用同一物体参数。

**未找到已验证的普通远程玩家直接挂 AIC 接口。**
控制权委托不等于创建 AI 控制器。通知 414（0x19e）的 TAG 路径会建立独立支援实体，
不能据此把既有 Robot 队员变成人偶。重新召唤一个人偶也不是 Robot 本体已会攻击。

证据：`puppet-professions-v25/review.json`、`combat-v3/puppet-trigger-review.private.json`、
`combat-v33/`、`burst-004006/puppet-summary.private.json`；原综合笔记
`x/dnf-gm-output/人偶攻击触发与Robot方案.md` 和 `x/Robot人偶战斗调研-20261120.md`。

## 移动、目标和普攻的协议知识

### 移动是多实体增量，静止不等于对象过期

命令 4 的位置在字段 9／10／11；字段可能显式给值、置零或沿用旧值，不能固定偏移读两个 float。
已有 10413 条原记录、10787 个实体的 Go 读写逐字节回放。
跟随只取队长玩家，不能复制队长控制的怪物移动。

房间内维护创建、位置、死亡、销毁，换房重置。
真实记录中存活怪物可 9.711 秒不发新坐标；以三秒无移动认定死亡／过期会丢失合法目标。
保留存活目标，依据死亡、销毁和换房清理，相关修复为 `57d622b`。

navigation-v2 中自主步长至多约 40 像素、间隔至少 200 ms；接近攻击距离后站稳，
最后目标消失回队，换房重新找怪。初始房间坐标重置必须与自主步长分开统计。
换房加载期间丢弃旧排队动作，见 `be0264c`；施法期间暂停导航，恢复后继续。

### 普攻要保留职业阶段

男魔法师真实 X 四连段为状态 8、参数 0/1/2/3，不能不停重发首段。
同目标存活、位置有效、在攻击范围且前段确认后才接下一段；失败不推进。
目标改变、死亡、移出范围、动作超时及换房中断连段。
350 ms 是现实现调度下限，实测约 400 ms；不是所有职业的动画周期。

combat-v18 采到五次完整连段和 43 对 Robot 来源命中；combat-v32 产品路径实机采到
165 次普攻状态、155 条命中、150 条 HP_DAMAGE 以及 51 次回队移动。
消息数未去重，不能当总伤害或击杀数；真人仍有被动装备，不能按清场画面独占归因。
静止目标的长期分支由历史原包回放验证，不冒充该轮新增静止场景实战。

证据：`navigation-v2/validation.private.json`、`navigation-v3/skill-integration.private.json`、
`combat-v18/combo-review.private.json`、`combat-v32/`。

## 完整技能：通知、状态和物体不能互相替代

| 消息／数据 | 已确认用途 | 容易重复犯的错误 |
| --- | --- | --- |
| UDP 25（十进制） | 11 字节：角色引用 4、技能 1、等级参数 1、剩余 MP 4、标志 1；真实样本先于 UDP 5 状态 | 把 MP 当消耗量；把只发状态当完整施法；标志 1 或有效等级写入语义尚无动态证明 |
| UDP 5 | 动作状态及参数向量 | 随便挑状态号、无准备／释放阶段、参数未匹配职业脚本 |
| TCP 41 | 字段宽度 1/1/2/2；该原 ELF UseSkill→OnUsedSkill 链负责校验／队伍统计 | 以为补发后服务端会自动扣 MP／材料 |
| 创建物体 0x15 | 除普通 XOR 外还有滚动 32 位掩码；尾部记录 key、发送者、长度，非四字节尾部另处理 | 固定偏移解析所有物体；直接复用真人伤害夹具 |
| HP_DAMAGE | 已确认 44 字节布局，按受击者引用及 +30 最终 HP 更新目标 | 读攻击者引用，或把同一最终 HP 当增量再扣一次 |

UDP 25 的真实对照为 v29：旋风三次、冰球三次、后跳两次，随后出现状态 20／43／6。
同帧时间戳相同仍要保留记录顺序；期间自然回蓝，不能拿相邻通知相减当技能消耗。
早期 v18/v19 没有该技能通知，不能从那些包证明完整主动技能链。

技能向量使用高位组在前的 base-128 编码。例如真实人偶 `02 03 87 5d` 为 `[2,3,989]`，
不是固定三字节小端整数。鬼剑士状态 23 空参数在两次实验中复现客户端
`0x4000001f`／偏移 `0x00264920`，当前实验配置与发送前拒绝该组合。
带参数未崩溃也不表示已攻击；未知技能注册／状态映射不能从全脚本随便找一个技能号猜测。
自定义 `sqr/` 入口需要参与提取，避免路径重复加 `sqr/`，技能号 -1 的注册继续排除。

外部探针曾对 Robot 委托控制并创建 24337，仅传分支和实际附近目标数，
由该 Robot 的技能／属性计算出真实命中，未传真人固定伤害。
连续准备、释放、创建、恢复的原语有两次命中及死亡 HP；它仍未接入生产自动技能调度。
更早旋风实验使用真人伤害夹具，只作为协议原语；不得将这份伤害参数发布。

证据：`combat-v4/review.private.json`、`combat-v5/skill-vector-review.private.json`、
`combat-v6/`、`resource-protocol-v27/resource-review.private.json`、
`skill-wire-v29/live-skill-wire-review.private.json`、`skill-execution-v28/`。

## 冷却、MP 消耗和自身资源：三层数据分别处理

### 逐级基础表已经有对照

- v31 对照 41 项技能、2421 个冷却值。旧解析器丢弃变化表，也丢失未闭合 `[dungeon]` 段，
  导致瞬移 1500 ms 读成零。支持开放段、隔离其他模式、按有效已学等级选逐级表。
  插值每步 float32，最后截断，不能一概用整数除法。
- v37 对照 43 项有明确 PVF 声明的技能、2442 个基础 MP 值；62 项缺声明保留未知。
  明确零和未知必须区分。51 条已注册 SQR 状态中 47 条得到基础表。
- 新夹具必须包含正确 `#PVF_File` 头；曾因夹具缺头使文本读取裁去开头方括号，
  不应因此修改产品解码器。元数据变动需要导出／缓存版本更新。

证据：`cooldown-v31/`、`base-mp-v37/`；对应代码提交 `e84d51f`、`2186d68`。
这些是基础元数据通过，不是完整施法或最终资源通过。

### 装备、有效等级与真实消耗已有真人对照

同一武器可把已学技能有效等级从 1 提为 2，未学技能仍为 0。
基础 MP 表在穿卸装备时保持不变，但实际消耗另有装备修正。
已实际采到武器前后两处修正，例：冰球修正前查询 11 经 float32 1.1 修正、截断后为 12；
真人实际旋风／冰球／后跳扣 6／12／1 MP，与成功消耗链一致。
不能只使用数据库基础技能等级，也不能给所有职业套一个固定倍率。

技能 24 请求材料 3037×1 实际被拒，未进入消耗和 TCP 消息构造。
这是拒绝路径证据，成功材料消耗仍没有完成。观察器曾取错发送器调用约定，
前三次漏掉结束记录；“没采到”不等于客户端“没发”。

证据：`client-loading-v23/`、`resource-v26/`、`resource-protocol-v27/`。

### 普通 Robot 最终资源入口已经定位，不能再从数据库 maxMP 开始猜

v38 同一 Robot 的通知 2 解密后还须 zlib 解压。原 ELF 属性段为 82 字节加一字节附加属性。
原通知和客户端原始输入均为 HP/MP 1800/1400；该客户端基础池经实际 10.0 常量缩放为 180/140，
后续装备和属性计算后为最终 1344/642。真人同轮为 1256/590。
数据库 maxMP 1400 不能当可用 MP，也不能用“统一除十”替代全部后续计算。
副本模式可有独立修正表；当时未保留其开关原字节，只能说该轮基础值符合有效系数 1，
不能据此断言该模式修正永远关闭。

v39 为静态追踪，没有新实机：`0x81fca0` 从最终池取修正属性，经非负截断和模式修正，
分别除以保护浮点全局 `0x1adc638`、`0x1adc650` 后加入 HP／MP 乘数。
v38 两除数均为 250，Robot 属性 97／139 对应 1.388／1.606，与现场吻合。
后半段还有恢复属性、资源随上限调整等逻辑，不能把这一段当完整公式。
`0x83e950` 和 `0x83b4b0` 带本地角色身份条件，真人与远程队员不能简单套同一公共倍率。

地址只适用于上表客户端身份；反汇编从完整函数入口开始，跨段跳转先核对输入／加载快照字节。
v39 选定跳转的字节一致只覆盖选点，不证明整个客户端内存完全一致。
观察器的旧 `job` 实为 +0x3658 原始字段，后改名 `raw_3658`，不能当职业。
备用分配对象 MP -1 不是已确认 Robot 的真实对象。

已排除：UDP 11 是装备相关同步；旧 25 条 UDP 13 均属真人恢复；`0x513030`／虚方法 +0x73c
属于经验初始化。不能再把这些当 Robot MP 初始化证据。
证据：`combat-v34/`、`contact-v36/`、`resource-model-v38/`、`final-resources-v39/`。

## 普通 Robot 受击仍是独立问题

修正 HP_DAMAGE 读取只解决已有伤害消息的归属和目标 HP，不会生成缺失的 Robot 本体碰撞。
v34/v35/v36 现场中的受击均指向真人，仍没有 Robot 本体受击入口／对应消息。
v36 真人和 Robot 的选定虚表／虚方法相同、控制者均为 0，不能据此认定初始化完全相同。

重建一条怪物碰撞请求并只改目标和位置，没有对应 Robot HP；包内仍有未知字段，
不能当成正确碰撞协议的失败证明。公共 HIT_OBJECT 分发出现在调用栈，也不足以证明由 Robot 发起。
下一步需要实际本体碰撞执行链、真实控制判定和完整对象初始化对照，不能定时扣血伪造受击。

证据：`combat-v4/`、`received-v35/`、`contact-v36/`。

## 采集和归因中已经踩过的坑

| 误判／失败 | 应复用的处理 |
| --- | --- |
| 掉血／清怪都算 Robot 的 | 真人称号冰波会产生 700021；卸下并按物体引用关联创建→命中→HP，不能只看画面 |
| 探针响应的 `owner:27` 就是实际控制者 | 该字段曾只是操作标签；实际控制权来自此前 TX 的 26，应核对线上包 |
| 黑屏和角色指针 0 就是加载死锁 | v23 正常按 Esc 后进入服务器选择；先完成正常界面流程，不反复等待无效指针 |
| 截图标签写“副本”就已入图 | 早期快照仍在城镇；以房间确认及双方对象快照为准，同区域后再一起进入 |
| 模块地址不符也继续安装探针 | 有一次入口字节核对拒绝，保持拒绝，不能跳过保护获取结果 |
| 采集器无事件说明原函数无执行 | 先核对调用约定、对象指针、钩子入口和结束记录，再作阴性结论 |
| 观测器脱离导致异常也写正常结束 | v35 脱离后 c0000409 已保留；v36 保留观察器直到正常关闭无新增错误，但钩子集也变化，根因尚未独立证明 |

原客户端异常、外部探针错误和 Native 服务端崩溃必须分开记录；客户端出错不代表 game 同时崩溃。
恢复也分层：原 ELF／PVF／客户端、临时配置／探针、目标数据库行、正常游戏存档各自核对。
卸掉称号或保留正常存档后，不能宣称整个研究库恢复到最早基线。

## 继续研究的最短路径

1. 从实验分支现有元数据、导航、普攻和真实消息解码接续，先核对上述基线；不用重新召唤五职业人偶或再采同一套基础表。
2. 以 v38/v39 已定位的资源链补齐实际装备／属性／模式输入及最终资源，未知值明确保留，不制造 MP。
3. 将技能通知、有效等级、最终剩余资源、准备／释放／恢复和物体创建组成同一职业的完整链，再扩展技能。
4. 独立解决普通本体实际受击及控制判定，保留角色身份；不能改成另一个召唤实体。
5. 在真实客户端逐项确认寻怪、攻击、怪物反击、清场回队、同区域换图，再考虑更多职业及策略。

只有新资源／客户端版本、反例或当前证据未覆盖的语义才重开对应实验。
一般性登录重试／空排空修复可单独提取，见 [运行知识](knowledge.md#登录拒绝与空排空修复保存在哪个分支)，
不需把整个战斗实验分支合入联调版本。
